# 🏗️ Архитектура системы

## Общий обзор

Restaurant App построен по принципам **чистой архитектуры (Clean Architecture)** с чётким разделением ответственности между слоями.

```
┌─────────────────────────────────────────┐
│             Клиент (React SPA)          │
└──────────────────┬──────────────────────┘
                   │ HTTP/REST
┌──────────────────▼──────────────────────┐
│          Nginx (reverse proxy)          │
└──────────────────┬──────────────────────┘
                   │
┌──────────────────▼──────────────────────┐
│            Go HTTP сервер               │
│  ┌──────────────────────────────────┐   │
│  │    Controllers (HTTP handlers)   │   │
│  ├──────────────────────────────────┤   │
│  │      Usecases (бизнес-логика)    │   │
│  ├──────────────────────────────────┤   │
│  │    Repositories (работа с БД)    │   │
│  └──────────────────────────────────┘   │
└──────┬───────────────────┬──────────────┘
       │                   │
┌──────▼──────┐   ┌────────▼────────┐
│ PostgreSQL  │   │     MinIO       │
│  (данные)   │   │  (изображения)  │
└─────────────┘   └─────────────────┘
```

## 🔧 Бэкенд

### Слои архитектуры

| Слой | Директория | Назначение |
|------|-----------|------------|
| **Domain** | `backend/domain/` | Сущности, интерфейсы репозиториев и юзкейсов |
| **Repository** | `backend/repository/` | Реализация работы с базой данных через GORM |
| **Usecase** | `backend/usecase/` | Бизнес-логика приложения |
| **Controller** | `backend/api/controller/` | HTTP-обработчики запросов |
| **Route** | `backend/api/route/` | Определение маршрутов API |
| **Middleware** | `backend/api/middleware/` | Аутентификация, проверка прав доступа |
| **Bootstrap** | `backend/bootstrap/` | Инициализация приложения, конфигурация, миграции |
| **Setup** | `backend/setup/` | Внедрение зависимостей (Dependency Injection) |

### Поток обработки запроса

```
HTTP Request
    │
    ▼
Middleware (JWT validate / Admin check)
    │
    ▼
Controller (парсинг запроса, вызов юзкейса)
    │
    ▼
Usecase (бизнес-логика, оркестрация)
    │
    ▼
Repository (GORM запрос к PostgreSQL)
    │
    ▼
HTTP Response (JSON)
```

### Внутренние сервисы

| Сервис | Директория | Назначение |
|--------|-----------|------------|
| **Mailer** | `backend/internal/mailer/` | Отправка email (Gomail + Яндекс SMTP) |
| **Scheduler** | `backend/internal/scheduler/` | Автоматическое обновление статусов заказов |
| **TokenUtil** | `backend/internal/tokenutil/` | Генерация/валидация JWT |

## 🌐 Фронтенд

### Архитектура React SPA

```
src/
├── App.tsx                  # Корневой компонент
├── components/
│   ├── router/              # AppRouter (публичные/приватные/admin маршруты)
│   ├── pages/               # Страницы приложения
│   ├── header/              # Заголовок (авторизован / гость)
│   ├── ui/                  # MUI тема и переиспользуемые компоненты
│   └── ...                  # Прочие UI-компоненты
├── api/
│   ├── api.ts               # Axios клиент с JWT interceptors
│   ├── services/            # Сервисы для вызова API
│   ├── models/              # DTO, request/response модели
│   └── polling/             # Polling для отслеживания заказов
└── store/
    ├── store.ts             # Redux конфигурация
    ├── authSlice.ts         # Состояние аутентификации
    ├── cartSlice.ts         # Корзина покупок
    └── addressSlice.ts      # Адрес доставки
```

### Управление состоянием (Redux)

| Slice | Назначение |
|-------|-----------|
| `authSlice` | Токены, данные пользователя, флаг администратора |
| `cartSlice` | Элементы корзины, итоговые суммы |
| `addressSlice` | Сохранённые адреса доставки |

### Маршрутизация

Маршруты разделены на три уровня доступа:

- **Публичные** — доступны без авторизации (`/`, `/menu`, `/booking`, `/login`, `/signup`)
- **Приватные** — требуют JWT токен (`/profile`, `/checkout`, `/orders`, `/gift`, `/user-booking`)
- **Административные** — требуют права администратора (`/admin`, `/admin/menu`, `/admin/booking`)

## 🔐 Безопасность

- **JWT**: Access token (2 часа) + Refresh token (168 часов / 7 дней)
- **Хранение**: Токены хранятся в `localStorage`
- **Авто-обновление**: Axios interceptor автоматически обновляет access token при 401
- **Пароли**: bcrypt хеширование
- **Права доступа**: Middleware проверяет admin-флаг в JWT claims
- **Email-верификация**: Временные токены для сброса пароля

---

## ⚡ Реальное время

Для отслеживания статуса заказов используется **polling** (опрос сервера с интервалом), поскольку WebSocket не требуется для данного типа нагрузки.

Scheduler на бэкенде автоматически обновляет статусы заказов каждую минуту.
